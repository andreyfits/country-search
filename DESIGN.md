# DESIGN.md — Country Search

## 1. Отмена устаревших запросов

Проблема: при быстром вводе (`sp` → `spain`) ответ на ранний запрос может прийти
позже ответа на поздний и перезаписать актуальный результат устаревшим — гонка ответов.

Решение — **реальная отмена через `AbortController`**, а не фильтрация по таймстампу:

- `SearchController` (`src/controller.ts`) хранит единственный активный
  `AbortController` в поле `inFlight`.
- На **каждое изменение ввода** (`setQuery`), ещё до срабатывания debounce,
  вызывается `abortInFlight()` → `controller.abort()`. Это ключевой момент:
  отмена происходит в момент ввода, а не когда срабатывает debounce-таймер —
  иначе за время задержки устаревший ответ успел бы отрендериться.
- `fetch` получает скомпонованный сигнал (см. ниже) и браузер прерывает
  HTTP-запрос физически (в Network tab — `canceled`), освобождая сокет и
  не тратя трафик.

Почему не флаг «актуальный ли ответ»: флаг лишь игнорирует результат постфактум —
запрос продолжает висеть в сети, грузить API и расходовать лимиты/трафик.
`abort()` устраняет причину, а не симптом, и является идиоматичным
механизмом платформы: fetch/сигналы интегрируются с сетевым стеком браузера.

Различение ошибок (`src/errors.ts → classifyError`):

- `AbortError` — отмена нами же → молча игнорируется, пользователю ничего не показывается.
- `TimeoutError` — сработал наш `AbortSignal.timeout` → настоящая ошибка с кнопкой «Повторить».
- `HttpError` — сервер ответил не-OK статусом (кроме 404) → ошибка с «Повторить».
- прочее (`TypeError` от fetch и т.п.) — сетевая ошибка.

Дополнительная защита в `performSearch`: ссылка `this.inFlight !== controller`
гарантирует, что даже если промис старого запроса резолвится (нестандартный
fetch-мок), его результат не попадёт в состояние.

## 2. Таймаут

`searchCountries` (`src/api.ts`) принимает один `signal` от вызывающего,
но отменяться должен и по новому вводу, и по таймауту. Оба источника
скомпонованы: `AbortSignal.any([callerSignal, AbortSignal.timeout(8000)])`
(есть ручной fallback для окружений без `AbortSignal.any`).
Таймаут приходит как `DOMException` с `name === 'TimeoutError'` — отличим
от нашей `AbortError` по имени.

## 3. Задержка debounce — 300 мс

`DEFAULT_DEBOUNCE_MS = 300` (`src/controller.ts`).

- Без debounce каждый keystroke = HTTP-запрос: лишняя нагрузка на API и
  каскад отмен, сетевой шум.
- Слишком большая (1 с+) — приложение ощущается «задумавшимся», ввод
  опережает отклик.
- 300 мс — стандартный компромисс: быстрый набор слова схлопывается в один
  запрос, а для одиночной правки задержка почти незаметна.

При этом отмена предыдущего запроса НЕ ждёт debounce — она происходит
синхронно на каждый `input`.

## 4. Сложность (Big O)

- `mapCountryResponse` (`src/mapper.ts`): O(L + C + B), где L/C/B — длины
  массивов языков/валют/границ страны. Это малые ограниченные списки
  (до нескольких десятков), поэтому практически O(1) на страну.
- Кэш и дедупликация (`src/cache.ts`): `Map` по строке запроса —
  O(1) на lookup/insert; память O(K), K — число уникальных запросов за сессию.
- `searchCountries` поверх: O(N·M) на маппинг N стран с максимумом M полей-списков.

## 5. Принципы чистого кода и где применены

- **Разделение слоёв**: вся логика (debounce/api/mapper/errors/controller/cache)
  не зависит от DOM — DOM только в `src/ui.ts`, точка входа `src/main.ts`
  лишь связывает слои. Тестируется без браузера и сети.
- **SRP**: одна функция — одна задача: `debounce` (таймер), `searchCountries`
  (сеть+семантика статусов), `mapCountryResponse` (чистый маппинг),
  `classifyError` (классификация), `SearchController` (оркестрация).
- **Чистая функция** `mapCountryResponse` — без побочных эффектов, не мутирует
  вход (проверено тестом).
- **DI**: `SearchController` получает `search`-функцию и колбэки через опции —
  в тестах подставляется мок, в проде `createCachedSearch(searchCountries)`.
- **Именование по намерению**: `abortInFlight`, `detached`, `NOT_FOUND_STATUS` —
  читается без комментариев.
- **Нет магических чисел**: `REQUEST_TIMEOUT_MS`, `DEFAULT_DEBOUNCE_MS`,
  `MAX_ENTRIES`, `NOT_FOUND_STATUS` — именованные константы.
- **Fail-safe в UI**: рендер через `createElement`/`textContent`, без
  `innerHTML` — нет XSS-поверхности на данных API.
- **Обработка ошибок без глотания**: `AbortError` осознанно пропускается
  (это не ошибка), всё остальное доходит до пользователя как error-состояние.

## 6. Бонус: кэш и дедупликация

`createCachedSearch` (`src/cache.ts`):

- `fulfilled: Map<query, Country[]>` — повторный одинаковый запрос отдаётся
  мгновенно, без сети.
- `inFlight: Map<query, Promise>` — повторный запрос, пока первый ещё летит,
  переиспользует тот же промис (нет второго HTTP-запроса).
- Каждый вызывающий получает «отцепленную» копию промиса (`detached`):
  его собственный `signal` может отменить _его ожидание_, но не разделяемый
  запрос — остальные подписчики не пострадают.
- Ошибки не кэшируются: неуспешный запрос удаляется из `inFlight` и может
  быть повторён.

## 7. Бонус: история поиска

`src/history.ts` — последние 10 уникальных запросов в `localStorage`
(ключ `country-search:history`), дедупликация, защита от недоступного
хранилища. Клик по чипу подставляет запрос в поле и вызывает `setQuery` —
попадание в кэш даёт мгновенный результат.
